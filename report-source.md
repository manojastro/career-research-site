## 600-hour roadmap
### Weeks 1–6 · 90 hours — Build your engineering foundation
Python functions/classes, typing, exceptions, async, package environments, debugging and pytest. Git branches/PRs; HTTP, REST and JSON; SQL joins, CTEs, windows, transactions and indexes. Learn probability, precision/recall and sampling only to the depth needed to evaluate systems.
Build: Build an incident ingestion API with FastAPI and Postgres. Add validation, pagination, structured logs, tests and CI. Explain every important line without an AI assistant.
Gate: implement a small API change and debug a failing test independently; write joins and aggregate queries on incident data.
Sources: [Python tutorial](https://docs.python.org/3/tutorial/); [Git fundamentals](https://docs.github.com/en/get-started/learning-to-code/getting-started-with-git); [PostgreSQL tutorial](https://www.postgresql.org/docs/current/tutorial.html)

### Weeks 7–12 · 90 hours — Deploy and operate one cloud service
Azure identity and managed identity, networking, secrets, storage, Container Apps or App Service, Azure Monitor, Docker, GitHub Actions and infrastructure as code. Choose one cloud; use AWS instead if you already have stronger AWS delivery experience.
Build: Deploy the API with repeatable configuration, scoped permissions, logs, alerts, cost budget and a rollback runbook. Trigger a failure and demonstrate recovery.
Gate: rebuild the environment from documented steps, rotate credentials safely, diagnose a broken deployment and explain a cloud bill.
Sources: [Azure administrator learning](https://learn.microsoft.com/en-us/credentials/certifications/azure-administrator/); [Docker getting started](https://docs.docker.com/get-started/); [GitHub Actions](https://docs.github.com/en/actions/get-started/quickstart)

### Weeks 13–20 · 120 hours — Ship your first evaluated AI application
LLM tokens/context, structured output, tools, embeddings, chunking, metadata, vector and keyword search, reranking, citations, abstention, rate limits and cost. Start with a direct API and a simple retrieval pipeline before adding an orchestration framework.
Build: Build the Enterprise Knowledge & Incident Copilot. Create 150 representative questions with expected evidence, including missing-answer and unauthorized-access cases; compare a basic pipeline with an improved version.
Gate: publish reproducible retrieval and answer-quality results, latency and cost; explain failure cases. Begin targeted applications when Python/cloud gates also pass.
Sources: [Azure RAG design and evaluation](https://learn.microsoft.com/en-us/azure/architecture/ai-ml/guide/rag/rag-solution-design-and-evaluation-guide); [AI-103 curriculum](https://learn.microsoft.com/en-us/credentials/certifications/resources/study-guides/ai-103)

### Weeks 21–28 · 120 hours — Build reliable agents and automation
Tool contracts, state, timeouts, retries, idempotency, approval steps, bounded loops, traces, evals and MCP. Select one agent framework after you can implement a simple tool loop. Read protocol/library versions when implementing.
Build: Extend the copilot into incident triage with a mock ticketing tool and an approval-controlled action. Add a test-intelligence project using your Selenium/API background.
Gate: demonstrate recovery from failed tools and duplicate events, audit every action, and run 50+ realistic scenarios with clearly reported success and failure rates.

## Portfolio briefs
### Enterprise Knowledge & Incident Copilot
Flagship · 80–100 project hours inside the roadmap
GenAI / Cloud AI / Solutions Engineering
A technician asks a question about a system incident and receives an evidence-linked answer grounded in approved runbooks.
FastAPI → retrieval service → Postgres/pgvector or Azure AI Search → model → cited response. Store document source, revision and access scope; enforce authorization before retrieval.
Start with 50 synthetic runbooks and 150 labeled questions. Split tuning and held-out evaluation sets. Include stale docs, conflicting instructions, missing answers and restricted content.
Measure retrieval recall@5, correct/grounded answers, appropriate abstention, p50/p95 latency and cost per answer. Compare keyword-only, vector and hybrid retrieval on the same set. Set acceptance thresholds before tuning; report actual results.
Deliver a 5-minute demo, reproducible ingestion, evaluation report, CI, cloud deployment, cost estimate and an architecture decision explaining the retrieval choice.
Reference: https://learn.microsoft.com/en-us/azure/architecture/ai-ml/guide/rag/rag-solution-design-and-evaluation-guide

### Incident Triage & Reliability Agent
Extend the flagship · 50–70 project hours
AIOps / Intelligent Automation / AI Deployment
An alert becomes a structured incident hypothesis, supporting evidence and a proposed next action for an engineer to approve.
Synthetic telemetry → rule/statistical baseline → correlation → retrieval → bounded agent → mock ticket API → approval → audited action. Keep causality claims provisional.
Build 50 labeled incident scenarios: duplicate alerts, missing telemetry, timeouts, misleading runbooks and permission failures. Include a deterministic baseline so you can show where AI adds value.
Measure top-k useful hypotheses, false escalations, scenario completion and simulated triage time. Inject tool failures and prove duplicate events do not create duplicate actions. Label all MTTR claims as simulation unless measured in real operations.
Deliver event replay, trace examples, an incident timeline, approval audit, rollback runbook and a concise failure postmortem.
Reference: https://learn.microsoft.com/en-us/azure/azure-monitor/aiops/aiops-machine-learning

### Test Intelligence & Release Assurance
Second standalone proof · 50–70 project hours
AI Automation / GenAI Engineering / QA-to-AI bridge
Convert an API change into proposed risk-based tests, run the suite, and explain failures with links to evidence.
OpenAPI or requirement diff → test proposals → human review → pytest/Selenium runner → deterministic results → failure clustering and summary. Execute generated code only in a constrained test environment.
Use a deliberately buggy sample service and a held-out set of seeded faults. Compare human-written baseline tests with reviewed AI suggestions. Record false alarms and duplicate tests.
Measure seeded-fault detection, useful test acceptance, flakiness across repeated runs and time-to-diagnose in a lab. Report test quality rather than lines of generated code.
Deliver PR examples, CI checks, failure replay, benchmark methods and a demo that explains one defect from change to diagnosis.
Reference: https://docs.github.com/en/actions/get-started/quickstart

### Secure Operations Tool Gateway
Flagship security module · 30–50 project hours
Secure AI Deployment / AI Security foundation
An AI client can inspect permitted asset/ticket information and request a controlled action with a complete audit trail.
MCP-compatible server → scoped identity/authorization → typed tool allowlist → mock CMDB/ticket tools → redacted audit log. Implement the current specification and record the version.
Test tenant-crossing requests, forged identity claims, malicious retrieved text, oversized inputs, repeated calls and tool failures. Include negative authorization tests independent of the model.
Measure policy-test pass/fail and unintended side effects. Demonstrate that prompt text cannot grant privileges and that retries remain idempotent.
Deliver threat model, protocol/integration tests, scope matrix, red-team results and an explicit limitations section. This proves a security foundation, not senior security expertise.
Reference: https://modelcontextprotocol.io/specification/
